Chapter Two

The Gate Is Open

Anyone on Telegram can message the bot, and the bot can run commands.

The risk

  • The bot is public
  • The AI can run commands
  • A tricked AI could reach my server

What I locked down

  • One sandbox per user
  • Files are read-only
  • Memory is capped
  • Server logins need a key, not a password

Chapter Three

The Key Under the Mat

I pushed the bot’s secret key to GitHub. I had to revoke it.

Step 1

Keep it out of the code

A locked vault on GitHub (GitHub secrets)

Step 2

Hand it over once

A secure link to the server (SSH)

Step 3

Sticky note

Held in memory, never saved to disk (Docker secrets)

Step 4

Read, then gone

The bot reads it only when needed

⚠

Never in plain settings (environment variables). Anyone with server access can read them there.

Chapter Four · Observability

The Mind Flayer

I could not see inside the bot, and what I could see I should not have kept.

What went wrong

  • Logs filled my disk
  • They stored what people typed
  • Errors scrolled away before I could read them

The fix

  • Track when and how long, not what was said
  • Users see plain error messages
  • A health check after every deploy

Should I stay or should I roll back?

What the day job taught me, applied to a side project

01

Isolate every user

If an agent can run commands, give each user their own sandbox.

02

Plan your logs early

Decide what you keep, where it goes and how big it can get.

03

Treat every bot as public

Keep secrets out of code and environment variables from the start.

And it stayed cheap: under $3 every two months in beta, on a free model, Telegram and a small rented server.
